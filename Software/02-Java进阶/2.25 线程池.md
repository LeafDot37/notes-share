# 线程池

频繁创建和终止大量线程会带来大量开销，线程池就可以解决这个问题。

![[Software/images/2/1795113394154.png]]

线程池简单来说，就是将多个线程打包到一起，统一创建和销毁。任务都可以通过线程池进行计算，当没有任务时对应线程会进入休眠状态而不是直接销毁。

## 继承体系

线程池 `ThreadPoolExecutor` 继承 `AbstractExecutorService`，后者继承 `ExecutorService`，`ExecutorService` 继承 `Executor`：

```text
Executor
└── ExecutorService
    └── AbstractExecutorService
        └── ThreadPoolExecutor
```

![[Software/images/2/1795113651673.png]]

## 主要参数

| 参数 | 说明 |
| --- | --- |
| corePoolSize | 线程池中所保存的核心线程数 |
| maximumPoolSize | 线程池中允许的最大线程数 |
| keepAliveTime | 线程池中的空闲线程所能持续的最长时间（核心线程不会终止，非核心线程空闲到达最长时间后就会终止） |
| workQueue | 阻塞队列，存放等待执行的任务 |
| threadFactory | 创建线程的工厂，主要定义线程名 |
| handler | 拒绝策略 |

## 线程工厂

```java
new ThreadFactory() {
    int count = 1;
    @Override
    public Thread newThread(Runnable r) {
        return new Thread(r, "员工-" + count++);
    }
}
```

## 工作流程

线程池工作时按以下顺序处理任务：

1. 首先检查运行状态，确保线程池正常运行；
2. 若正在运行的线程数量小于核心线程数，那就创建并启动一个线程来执行任务；
3. 若任务数大于核心线程数，同时阻塞队列不满，那就放到阻塞队列中；
4. 若阻塞队列也满了，就创建并启动一个非核心线程来执行任务；
5. 若线程总数也超了，即线程池满了，就根据拒绝策略来处理任务。

## 拒绝策略

默认的拒绝策略为抛出异常。除此之外还有调用者执行、丢弃最旧任务、直接丢弃等策略，可根据业务对任务丢失的容忍程度选择。
