# 同步与死锁

## 数据不一致问题

当多个线程同时运行时，线程的调度由操作系统决定，程序本身无法决定，因此任何一个线程都有可能在任何指令处被操作系统暂停，然后在某个时间段后恢复运行。所以如果多个线程同时读写共享的变量，就会出现数据不一致的情况。

## 原子操作

一般在多线程模型下，要求做到原子操作。原子操作指不能中断的一个或一系列操作，要么完全执行，要么完全不执行。

比如一个 `n = n + 1` 操作，其本质是取数、加法运算、结果保存三步。在多线程模式下，就要保证这三步一组的指令以原子方式执行，即某一线程执行时，其他线程必须等待。

## 使用 synchronized 加锁

可以用 `synchronized` 关键字对一个对象进行加锁，保证同一时刻只有一个线程能进入临界区：

```java
synchronized (lock) {
    n = n + 1;
}
```

也可以把方法声明为同步方法，锁对象是当前实例（静态同步方法则是类的 Class 对象）。

![[Software/images/2/1795109410539.png]]

## 死锁

在使用锁的时候，要注意会出现死锁现象。例如：

- 在线程 A 中，持有蓝色钥匙，想要红色钥匙；
- 在线程 B 中，持有红色钥匙，想要蓝色钥匙。

这种情况下两个线程就会永远等待下去。

## 避免死锁

为了避免死锁现象，需要让线程获取锁的顺序一致，即都按照先获取蓝色钥匙、再获取红色钥匙的顺序。这样可以保证一个线程获取蓝色钥匙后，另一个线程会正常被阻塞，等前者释放后再继续，而不会形成循环等待。
