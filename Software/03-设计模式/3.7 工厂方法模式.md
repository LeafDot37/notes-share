# 工厂方法模式

把对象的创建延迟到子类，由子类决定实例化哪一种具体产品。

## 定义

工厂方法模式将对象的创建封装在类中：先定义一个抽象工厂方法，只设置返回的产品对象，供父类中的函数使用；而工厂方法的真正实现依赖于子类中的对象创建方法。

这样可以把一个产品的自身属性和它的创建解耦：创建者类继承于一个抽象类，而产品本身继承于另一个类。

## 角色

- 抽象创建者：声明抽象工厂方法 `createPizza`，并在自己的业务方法 `orderPizza` 中调用它。
- 具体创建者：实现工厂方法，决定创建哪一种具体产品。
- 抽象产品与具体产品：产品有自己的继承体系，与创建者的继承体系相互独立。

## 代码

```java
public abstract class PizzaStore {
    // 抽象工厂方法：只声明返回的产品对象
    abstract Pizza createPizza(String type);

    public Pizza orderPizza(String type) {
        Pizza pizza;
        pizza = createPizza(type);

        pizza.prepare();
        pizza.bake();
        pizza.cut();
        return pizza;
    }
}

public class NYPizzaStore extends PizzaStore {
    @Override
    public Pizza createPizza(String type) {
        Pizza pizza = null;
        if (type.equals("cheese")) {
            pizza = new CheesePizza();
        } else if (type.equals("greek")) {
            pizza = new GreekPizza();
        }
        return pizza;
    }
}
```

## 优缺点

- 优点：新增一种产品时，只需新增对应的具体创建者子类，不必修改抽象创建者和已有子类，符合开闭原则。
- 优点：创建逻辑与产品使用逻辑分离，父类的业务流程保持稳定。
- 缺点：每新增一种产品通常都要新增一个创建者类，类的数量会增加。
