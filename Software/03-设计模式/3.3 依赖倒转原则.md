# 依赖倒转原则

把高层模块与底层实现之间的直接依赖，倒转为双方都依赖抽象。

## 定义

依赖倒转原则（DIP，Dependency Inversion Principle）：高层模块不依赖底层模块，它们都应该依赖抽象；要针对接口编程，而不是针对实现编程。

## 具体做法

- 在变量类型声明、参数类型声明、方法返回类型声明时，使用接口或抽象类，而不是具体的实现类。
- 让具体类继承该接口或抽象类，由具体类提供实现。
- 高层模块只面向抽象编写逻辑，底层实现可以替换而不影响高层代码。

## 意义

- 高层业务逻辑不再被底层实现细节绑定，底层实现变化时高层无需修改。
- 同一抽象可以有多种实现，便于替换、扩展和测试。
- 与开闭原则配合，是面向接口设计的基础。
