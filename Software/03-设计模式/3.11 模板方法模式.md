# 模板方法模式

在抽象类中定义算法的骨架，把某些具体步骤延迟到子类实现。

## 定义

模板方法模式定义一个操作中的算法骨架，将其中一些步骤延伸到子类中。模板方法模式使得子类可以不改变一个算法的结构即可重新定义该算法的某些特定步骤。

## 角色

- `AbstractClass` 抽象类：给出抽象模板，定义并实现一个模板方法，给出顶层逻辑的骨架；同时声明一个或多个抽象方法。
- `ConcreteClass` 具体类：实现父类定义的一个或多个抽象方法。

一个抽象类可以有多个具体子类，每一个具体子类都可以给出抽象方法的不同实现。

## 代码

```java
public abstract class AbstractClass {
    public abstract void PrimitiveOperation1();

    public abstract void PrimitiveOperation2();

    public void TemplateMethod() {
        PrimitiveOperation1();
        PrimitiveOperation2();
        System.out.println("");
    }
}

public class ConcreteClassA extends AbstractClass {
    public void PrimitiveOperation1() {
        System.out.println("具体类A方法1实现");
    }

    public void PrimitiveOperation2() {
        System.out.println("具体类A方法2实现");
    }
}

public class ConcreteClassB extends AbstractClass {
    public void PrimitiveOperation1() {
        System.out.println("具体类B方法1实现");
    }

    public void PrimitiveOperation2() {
        System.out.println("具体类B方法2实现");
    }
}
```

## 优点

- 把不变的行为搬到超类，去除了子类中的重复代码，提高了代码复用。
- 算法的整体结构由父类统一控制，子类只关注需要变化的具体步骤。
- 子类可以在不改变算法结构的前提下重新定义某些步骤。

## 反向控制

在这个模式下，允许并且提倡抽象类靠具体类实现算法的具体细节：在抽象类中定义出整套流程，但其中具体实现交给具体类去做。

这会出现类似父类调用子类方法的操作，称为反向控制。流程的控制权从子类反转到父类，父类决定何时调用子类实现的步骤。

## 缺点

- 每一种不同的实现都需要一个具体子类，类的数量会增加。
- 模板方法中的可变步骤越多，子类需要实现的细节越多。
