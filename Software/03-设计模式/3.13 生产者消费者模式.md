# 生产者消费者模式

通过共享缓冲区解耦数据的生产与消费，并用同步机制协调两者的速度差异。

## 问题场景

在软件开发过程中，会碰到某个模块负责产生数据，这些数据由另一个模块负责处理的场景。产生数据的模块被称为生产者，处理数据的模块被称为消费者。

在生产者和消费者之间存在内存缓冲区：

- 如果消费者消费得慢、生产者生成得快，缓冲区达到最大后就会阻塞生产者。
- 如果消费者消费得快、生产者生成得慢，缓冲区空了后就会阻塞消费者。

如何保证缓冲区数据状态一致，以及消费者和生产者同步协作就非常重要，一般通过加同步锁或利用线程内部通信来完成。

## 代码

```java
import java.util.ArrayList;
import java.util.List;
import java.util.Random;

/**
 * 缓冲区类（Buffer）
 * 作为生产者和消费者共享的中间容器
 */
class Buffer {
    // 1. 数据存储容器
    private List<Integer> data = new ArrayList<>();

    // 2. 定义缓冲区的容量上限和下限
    private static final int MAX = 2; // 缓冲区最多容纳2个数据
    private static final int MIN = 0; // 缓冲区最少为0个数据（空）

    /**
     * 生产者调用的放入数据方法
     * @param value 需要放入的数据
     */
    public void put(int value) {
        // 生产者可以无限循环不断地生产数据
        while (true) {
            try {
                // 模拟生产者花费500ms生成数据的过程
                Thread.sleep(500);
            } catch (InterruptedException e) {
                e.printStackTrace();
            }

            // 3. 使用 synchronized 锁住当前 Buffer 对象，保证线程安全
            synchronized (this) {
                // 4. 核心逻辑：检查缓冲区是否已满
                while (data.size() == MAX) {
                    System.out.println("buffer is full, waiting ....");
                    try {
                        // 如果已满，当前生产者线程在 this (Buffer对象) 上等待
                        // 释放锁，并进入等待状态，等待消费者取出数据后唤醒它
                        wait();
                    } catch (InterruptedException e) {
                        e.printStackTrace();
                    }
                }

                // 5. 如果没有满，继续生产
                System.out.println("producer--" + Thread.currentThread().getName() + "--put:" + value);
                // 将数据添加到缓冲区
                data.add(value);

                // 6. 唤醒所有在 this 对象上等待的线程（包括其他的消费者和生产者）
                // 通知大家：我刚刚放了新数据，你可以来取了；或者缓冲区有空间了，你可以来放了
                notifyAll();
            }
        }
    }

    /**
     * 消费者调用的取出数据方法
     * @return 取出的整数数据
     */
    public Integer take() {
        Integer val = 0;
        // 消费者也可以无限循环不断地消费数据
        while (true) {
            try {
                // 模拟消费者花费500ms处理数据的过程
                Thread.sleep(500);
            } catch (InterruptedException e) {
                e.printStackTrace();
            }

            // 7. 同样需要获取 this (Buffer对象) 的锁
            synchronized (this) {
                // 8. 核心逻辑：检查缓冲区是否为空
                while (data.size() == MIN) {
                    System.out.println("buffer is empty, waiting ...");
                    try {
                        // 如果为空，当前消费者线程在 this 上等待
                        // 释放锁，进入等待状态，等待生产者放入数据后唤醒它
                        wait();
                    } catch (InterruptedException e) {
                        e.printStackTrace();
                    }
                }

                // 9. 如果有数据，继续消费
                // 取出列表中的第一个数据（FIFO 先进先出）
                val = data.remove(0);
                System.out.println("consumer--" + Thread.currentThread().getName() + "--take:" + val);

                // 10. 取出数据后，通知所有等待中的线程
                // 通知大家：我刚刚取出了数据，缓冲区有空间了，生产者你可以继续放了
                notifyAll();
            }
        }
    }
}

/**
 * 生产者线程实现类
 */
class Producer implements Runnable {
    // 持有 Buffer 对象的引用，通过构造函数传入
    private Buffer buffer;

    public Producer(Buffer buffer) {
        this.buffer = buffer;
    }

    @Override
    public void run() {
        // 每次执行时，生成一个 0-99 之间的随机数，放入缓冲区
        buffer.put(new Random().nextInt(100));
    }
}

/**
 * 消费者线程实现类
 */
class Consumer implements Runnable {
    // 持有 Buffer 对象的引用，通过构造函数传入
    private Buffer buffer;

    public Consumer(Buffer buffer) {
        this.buffer = buffer;
    }

    @Override
    public void run() {
        // 每次执行时，从缓冲区中取出一个数据
        Integer val = buffer.take();
    }
}
```

## 关键点

- `synchronized (this)` 锁住同一个 Buffer 对象，保证生产者和消费者对 `data` 的访问互斥。
- 判断缓冲区满或空时使用 `while` 而不是 `if`：线程被唤醒后会重新检查条件，避免条件在等待期间被其他线程改变。
- `wait()` 会释放持有的锁并让线程进入等待状态，使另一方能够进入同步块。
- `notifyAll()` 唤醒所有在该对象上等待的线程，生产者和消费者都可以重新竞争锁并检查条件。
- 缓冲区满时生产者等待，缓冲区空时消费者等待，从而把生产与消费的速率差异解耦。
