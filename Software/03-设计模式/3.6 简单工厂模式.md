# 简单工厂模式

用一个工厂类集中负责创建产品对象，调用方只与工厂打交道。

## 定义

简单工厂模式通过一个工厂类来创建产品对象（例如披萨）。这样在实现更复杂的功能时，可以在对应的复杂类中使用这个工厂类来创建产品对象。

## 结构

- 工厂类：提供一个创建方法，根据传入的类型参数决定实例化哪一种产品。
- 使用方：持有一个工厂对象，通过工厂获取产品，再调用产品的业务方法。

## 代码

```java
public class SimplePizzaFactory {
    public Pizza createPizza(String type) {
        Pizza pizza = null;
        if (type.equals("cheese")) {
            pizza = new CheesePizza();
        } else if (type.equals("greek")) {
            pizza = new GreekPizza();
        }
        // 新增披萨类别时，需要在这里继续添加分支
        return pizza;
    }
}

public class PizzaStore {
    SimplePizzaFactory factory;

    public PizzaStore(SimplePizzaFactory factory) {
        this.factory = factory;
    }

    public Pizza orderPizza(String type) {
        Pizza pizza;
        pizza = factory.createPizza(type);

        pizza.prepare();
        pizza.bake();
        pizza.cut();
        return pizza;
    }
}
```

## 为什么不算真正的设计模式

简单工厂并没有满足开闭原则：若要新建一个新的披萨类别，就必须对这个工厂类进行修改，在创建方法中增加新的分支。因为对修改没有关闭，所以严格来说它不算一种真正的设计模式，更多是一种编程习惯。

## 优缺点

- 优点：把对象创建集中到一处，使用方与具体产品类解耦，不必关心产品如何被创建。
- 缺点：工厂类承担了所有产品的创建逻辑，职责过重；新增产品必须修改工厂类，违反开闭原则。
