# 线程等待与通知

## 三种不活动状态

### 阻塞状态

当一个线程试图获取一个内部的对象锁，而该锁被其他线程持有，这时这个线程就会进入阻塞状态。当所有其他线程释放该锁，且线程调度器允许本线程持有它，该线程就会变成非阻塞状态。

### 等待状态

当线程等待另一个线程通知调度器一个条件时，进入等待状态。例如：

- 当前线程调用 `wait` 方法，进入等待状态，等待其他线程对象调用 `notify` 或 `notifyAll` 方法唤醒；
- 其他线程调用 `join` 方法，该线程会等待调用 join 方法的线程结束后再继续运行。

### 计时等待状态

有几个方法具有一个超时参数，调用这些方法时会使线程进入计时等待状态。例如当前线程调用 `wait(time)`、其他线程调用 `join(time)`、当前线程调用 `sleep(time)`，线程会在指定时间后自行返回到运行状态。

当线程处于阻塞状态或者等待状态时，它暂时不活动，不运行任何代码，直到线程调度器重新激活它。

## synchronized 与 Mark Word

每个 Java 对象在内存里都有一个对象头，对象头里有一块区域叫 Mark Word。`synchronized(t)` 会把当前线程的 ID 写进 `t` 对象头里的 Mark Word，这就叫当前线程拿到 t 的锁。之后如果别的线程也想 `synchronized(t)`，它会发现 Mark Word 里已经写着别人的线程 ID，于是只能去 `t` 的锁竞争队列（`_EntryList`）里排队等着。

## sleep、wait、notify、join 的区别

| 方法 | 所属 | 是否释放锁 | 说明 |
| --- | --- | --- | --- |
| `sleep()` | Thread 静态方法 | 否 | 作用对象永远是当前正在执行的线程；在 synchronized 块里 sleep，锁仍然在当前线程中 |
| `wait()` | Object 方法 | 是 | 必须放在 synchronized 块里调用；释放当前线程持有的对象锁，同时把当前线程放进这个对象的 `_WaitSet` 等待队列，线程进入 WAITING 状态，操作系统层面挂起 |
| `wait(long timeout)` | Object 方法 | 是 | 超时自动醒，进入 TIMED_WAITING 状态 |
| `notify()` | Object 方法 | 否 | 从 `_WaitSet` 里挑一个线程唤醒（即将线程从等待队列中放入竞争队列），具体挑哪个由 JVM 实现决定，不能假设顺序 |
| `notifyAll()` | Object 方法 | 否 | 唤醒所有等待线程 |
| `join()` | Thread 实例方法 | 否 | `t.join()` 表示当前线程等待线程 t 结束 |

要点：

- `wait()` 使用的条件判定必须是 `while` 而不是 `if`，这样可以在 notify 后重新拿到锁时再判定条件是否满足；
- `notify()` 和 `notifyAll()` 也是 Object 方法，必须放在 synchronized 块中调用，且 `synchronized` 锁定的对象必须和调用方法的对象是同一个。注意：被 notify 唤醒的线程需要重新竞争到锁才能从 wait 返回。

## 典型等待—通知代码

```java
// 将当前线程 ID 写入 lock 的头，当前线程获取 lock 的锁
synchronized (lock) {
    while (!condition) {
        // 释放当前线程持有的 lock 的锁，将这个线程放入 lock 等待序列
        lock.wait();
    }
}

// 当前面的 lock 锁被释放后，当前线程获取 lock 锁
synchronized (lock) {
    condition = true;
    // 在 lock 的等待序列中选一个线程唤醒
    lock.notify();
}
```
