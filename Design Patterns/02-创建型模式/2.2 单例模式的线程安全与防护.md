# 单例模式的线程安全与防护

解决懒汉式单例在并发下的多实例问题，并防止通过反射绕过私有构造方法。

## 线程安全问题

懒汉式中的 `if (instance == null)` 判断与 `new Singleton()` 创建并不是一个原子操作。多个线程可能同时通过判断，各自创建一个实例，从而破坏“唯一实例”的约束。

## 同步锁

通过添加 `synchronized` 关键字，使得每个线程在进入这个方法前，都要等别的线程离开该方法，即不会允许两个线程同时进入这个方法。

```java
public class Singleton {
    private static Singleton instance;

    private Singleton() {}

    public static synchronized Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}
```

这样同一时刻只有一个线程能执行创建逻辑，解决了并发下产生多个实例的问题。代价是每次获取实例都要加锁，访问开销增大。

## 反射破坏

单例模式有时可以通过反射来破坏。反射中的 `setAccessible(true)` 可以覆盖 Java 的访问控制，进而调用私有的构造方法，绕过 `getInstance` 直接创建新的实例。

## 构造器防护

为了抵御这种破坏，可以在构造方法中判断当前是否已经有了单例，如果已经存在就不再创建，而是抛出异常。

```java
public class Singleton {
    private static Singleton singleton = new Singleton();

    private Singleton() {
        if (singleton != null) {
            throw new RuntimeException("单例构造器禁止通过反射调用");
        }
    }

    public static Singleton getInstance() {
        return singleton;
    }
}
```

这种写法可以一定程度上抵御反射破坏：当反射再次调用私有构造方法时，静态实例已经存在，构造器直接抛出异常。但它并非绝对安全，例如反射仍然可以修改静态字段。
