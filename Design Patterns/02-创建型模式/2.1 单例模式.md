# 单例模式

保证一个类在整个程序中只有一个实例，并提供一个访问该实例的全局入口。

## 定义

单例模式保证一个类只有一个实例，并提供一个访问它的全局访问点。

具体实现最好的办法是让类自身负责保存它的唯一实例：这个类可以保证没有其他实例被创建，同时提供一个访问该实例的方法。

## 实现要点

- 用一个私有静态成员保存唯一的实例。
- 将构造方法私有化，使外部无法通过 `new` 直接创建对象。
- 提供一个公有的静态方法，返回这个唯一实例。

## 饿汉式

在类加载时就创建实例。

```java
public class Singleton {
    private static Singleton singleton = new Singleton();

    // 构造方法私有化，外部无法通过 new 直接创建实例
    private Singleton() {}

    public static Singleton getInstance() {
        return singleton;
    }
}
```

特点：实现简单，类加载过程只执行一次，天生线程安全；但实例在类加载时就被创建，即使从未使用也会占用资源。

## 懒汉式

在第一次调用获取实例的方法时才创建。

```java
public class Singleton {
    private static Singleton instance;

    private Singleton() {}

    public static Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}
```

特点：延迟加载，未使用时不会创建实例，节省资源；但多个线程同时调用时，可能都判断为 `null` 并各自创建一个实例，因此在多线程环境下不安全。

## 优缺点

- 优点：严格控制实例数量；懒汉式可以延迟创建、节省资源；提供统一的全局访问点。
- 缺点：单例本质上是全局状态，滥用会增加类之间的隐式耦合；懒汉式必须额外处理线程安全问题。
