# 观察者模式

定义对象之间一对多的依赖关系，当一个对象状态改变时，所有依赖它的对象都会得到通知并自动更新。

## 定义

观察者模式又称 MVC 模式。当一个对象的状态或行为的变化导致其他对象的状态或行为产生变化时，观察者模式定义了对象之间一种一对多的依赖关系，让一个对象的改变能够影响其他对象。

发生改变的对象称为观察目标，被通知的对象称为观察者，一个观察目标可以对应多个观察者。

## 角色

- 观察目标 Subject：维护一个观察者集合，提供注册（attach）和注销（detach）方法，并在状态变化时发出通知。
- 具体目标：实现通知方法，遍历观察者集合并调用每个观察者的响应方法。
- 观察者 Observer：定义响应接口。
- 具体观察者：实现具体的响应行为。

## 代码

```java
public abstract class MySubject {
    protected ArrayList observers = new ArrayList();

    // 注册方法
    public void attach(MyObserver observer) {
        observers.add(observer);
    }

    // 注销方法
    public void detach(MyObserver observer) {
        observers.remove(observer);
    }

    public abstract void cry();  // 抽象通知方法
}

public class Cat extends MySubject {
    public void cry() {
        System.out.println("猫叫！");
        System.out.println("--------");

        for (Object obs : observers) {
            ((MyObserver) obs).response();
        }
    }
}

public interface MyObserver {
    void response();  // 抽象响应方法
}

public class Dog implements MyObserver {
    public void response() {
        System.out.println("狗跟着叫！");
    }
}

public class Mouse implements MyObserver {
    public void response() {
        System.out.println("老鼠努力逃跑！");
    }
}

public class Client {
    public static void main(String[] args) {
        MySubject subject = new Cat();

        MyObserver obs1, obs2, obs3;
        obs1 = new Mouse();
        obs2 = new Mouse();
        obs3 = new Dog();

        subject.attach(obs1);
        subject.attach(obs2);
        subject.attach(obs3);

        subject.cry();
    }
}
```

## 优缺点

- 优点：实现了表示层和数据逻辑层的分离。
- 优点：在观察目标和观察者之间建立了一个抽象的耦合，双方不必了解对方的具体实现。
- 优点：支持广播通信，一个目标的变化可以通知多个观察者。
- 优点：新增观察者无需修改观察目标，符合开闭原则。
- 缺点：观察者数量较多时，逐个通知会带来额外开销。
- 缺点：观察者与目标之间若形成循环依赖，可能使通知过程变得复杂。
